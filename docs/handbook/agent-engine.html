04 · The Heart of ArimaOps

Agent Engine, Memory & Skills

How HQ launches real AI CLIs, talks to them reliably, enforces 11 workflow gates, remembers lessons in SQLite FTS5, and blocks malicious skill packs before an agent ever reads them.

1. Dual Execution Engine: Terminal vs Stream-JSON

Every agent runs inside a tmux session (hq-<project>-<agent>) on its own full git clone at ~/.arima/<project>/<agent>/. Depending on the agent's engine setting, HQ drives it through one of two engines:

Figure 4.1 · Terminal Engine vs Stream-JSON Engine Interactive Trace
Two Paths, One Orchestration Layer: Both engines share tmux persistence, Inbox queues, /mcp tools, and Hub state. Stream-JSON is opt-in per Claude Code seat in sandbox/container mode.

2. Per-CLI Adapters (server/adapters.ts & agentFiles.ts)

How does HQ support 6 different AI CLIs (claude, codex, agy, opencode, gemini, copilot) without 6 separate engines? Every CLI difference is isolated to two files:

  • agentFiles.ts: Writes the agent's role brief (.arima-role.md), Team MCP config (.mcp.json / TOML / JSON), and CLI hook scripts, adding all of them to .git/info/exclude so agent repos stay clean.
  • Deduplicated instructions: architecture-invariants-test.ts explicitly verifies that Gemini (via contextFileName) and Antigravity (.agents/rules/hq-role.md + .arima-role.md) never load duplicate copies of the role text—saving thousands of system-prompt tokens.
  • Container "YOLO" flags: Inside containers and sandboxes, the VM/container + egress proxy is the permission boundary, so containerArgs() automatically passes each CLI's non-interactive flag (e.g., --dangerously-skip-permissions for Claude, --yolo for Gemini) so agents don't stall on every shell command.

3. Templates, Flows & All 11 Gate Kinds

Every project is instantiated from a TeamTemplate copied into projects_model. A template defines roles (the Lead is never on-demand; workers can be on-demand), tool rules (findings, plans, scopeRequired, labMode, outbound, egress), and an ordered flow of stages guarded by gates (server/gates.ts).

Figure 4.2 · Dev Team v3 Pipeline (DEV_TEMPLATE in src/data/templates.ts) 5 Stages · 7 Gates
Other built-in templates swap in domain stages using the exact same gate engine: Security Red/Purple/Blue (PTES / NIST SP 800-61), Research (Sources → Claims → Fact-check → Report), Marketing, Sales, Startup, and Blank.

Stalls, Owner-Away & Stacked PRs: Every few minutes runStallCheck() (server/stalls.ts) watches for workers idle ≥ 5 min or silent while working ≥ 15 min: it nudges once, logs a stall entry to the Progress ledger, asks the Lead to replan on stall #2, and pushes the owner on stall #3. Meanwhile, Planner.stackBase allows a task whose only open dependency has an unmerged PR to branch on top of that PR and rebase cleanly when the parent merges.

4. Memory Core (SQLite + FTS5 + Privacy Scrubbing)

Originally prototyped against Neo4j, ArimaOps moved its entire memory graph cleanly into SQLite (server/memory.ts) with zero external daemon overhead:

  • Ledgers (ledger_entries): Task ledger (Lead's fact, guess, plan) and Progress ledger (HQ's stall, replan). Append-only: revisions create a new row and mark the old row superseded_by.
  • Memories + FTS5 + 1–2 hop graph: Memories (Decision, Lesson, DeadEnd, plus template types like Finding or Source) are indexed in virtual FTS5 table memory_text via SQLite triggers for instant recall(). related() walks memory_about file links and task_summaries dependencies up to 2 hops.
  • Safety & lifecycle (memoryClean.ts, memoryReview.ts, forget.ts): Every memory passes through cleanMemory() first—masking vault secrets, tokens, emails, phone numbers, public IPs, and project keep-out names. Uncertified memories fade after 30 days unused; Inbox lets you certify or reject them (contradictions against certified memories push urgently). forgetProject() wipes all project rows, anonymizes usage telemetry, deletes workspaces, and emits a printable deletion record.

5. Skills & Supply-Chain Security

Third-party agent skill repos are a real prompt-injection and RCE vector. ArimaOps refuses to run unpinned npx skills add installers. Instead, server/skillPacks.ts and server/skillScan.ts enforce a strict 5-stage pipeline:

Figure 4.3 · Skill Pack Verification Pipeline Zero-Execution Fetch
skillScan.ts blocks invisible Unicode tag characters (U+E0000–E007F), bidi overrides, agent prompt hijacks in plain prose ("ignore previous instructions", "do not tell the user", reading ~/.ssh/vault.json), CLI hooks files, curl | sh, and base64 -d | sh—while smartly stripping inline code spans and quoted strings so legitimate security-testing skills are warned rather than false-blocked.

Agent Engine Self-Check

1. When the owner has been away for 2 hours, which gates may the Lead pass on the owner's behalf, and what happens when the owner returns?
2. Why does server/skillScan.ts strip inline backticks and quoted strings before scanning Markdown prose for prompt-injection phrases?
3. Why does the Stream-JSON runner (server/streamRunner.ts) run inside tmux instead of HQ spawning claude -p as a direct child process?
