Six Progressive Hands-On Labs

You don't truly own a codebase until you inspect it live, fix a real bug, wire a command end-to-end, write a pure test, and ship a scoped UI + MCP change. Check off each lab as you finish it (saved in your browser).

Safety Before You Experiment

For Labs 2–5, work on a throwaway git branch (e.g. git switch -c learn/labs) so your main stays pristine, and use HQ_PORT=59999 pnpm exec vite --port 5178 --strictPort for safe UI testing without colliding with your live Docker HQ on :7420.

Lab 0 · Beginner · Ops

Inspect the Live System Without Breaking It

Goal: See the real processes, open ports, SQLite database rows, and mock UI running side by side.

Steps:

  1. Check Docker containers and listening HQ ports (`7420` & `8420`).
  2. Query the SQLite `docs` table read-only using Node's built-in `node:sqlite`.
  3. Run `pnpm test architecture-invariants` to see the invariant suite execute.
  4. Boot the offline mock UI on `:5178` and open `http://localhost:5178/?mock=1` in your browser.
Terminal Verification Commands
docker ps --filter name=arimaops
ss -tlnp | grep -E '7420|8420'
node -e 'const {DatabaseSync}=require("node:sqlite"); const db=new DatabaseSync(process.env.HOME+"/.arima/arima.db",{readOnly:true}); console.log(db.prepare("SELECT name FROM docs").all())'
pnpm test architecture-invariants
HQ_PORT=59999 pnpm exec vite --port 5178 --strictPort
What you should observe

You will see arimaops-hq-1 listening on 127.0.0.1:7420, 172.30.0.1:7420, and 172.30.0.1:8420; SQLite listing rows like projects.json, devices.json, and users.json; and the mock Command Deck rendering sample software and red-team teams without touching live HQ.

Reference solution snippet for arimaops-launch.sh
scripts/launcher/arimaops-launch.sh (updated sections)
# 1) Read recent projects from SQLite (fallback to legacy JSON)
recent=$("$NODE" -e '
  try {
    const fs = require("fs"), os = require("os"), path = require("path");
    const dbPath = path.join(os.homedir(), ".arima", "arima.db");
    let raw = null;
    if (fs.existsSync(dbPath)) {
      const { DatabaseSync } = require("node:sqlite");
      const db = new DatabaseSync(dbPath, { readOnly: true });
      raw = db.prepare("SELECT value FROM docs WHERE name = ?").get("projects.json")?.value ?? null;
      db.close();
    }
    const r = raw ? JSON.parse(raw) : [];
    const list = Array.isArray(r) ? r : r.projects ?? [];
    for (const p of list) if (p.path && fs.existsSync(p.path)) console.log((p.name || p.id) + "\t" + p.path + "\t" + (p.id || ""));
  } catch {}
' 2>/dev/null || true)

# 2) If HQ is already listening on :7420 (e.g. Docker Compose), open it directly
if curl -sf http://127.0.0.1:7420/api/health >/dev/null 2>&1; then

grep -rn "assignTask" src/ server/

Lab 3 · Intermediate · Backend + Contract

Add a Typed WebSocket Command

Goal: Add a new command pingTeam (accepts a short message string, emits an activity feed line via hub.activity) and make the compiler + invariant suite pass.

  1. Add pingTeam(note: string): void; to OfficeDataSource in src/data/source.ts.
  2. Implement pingTeam in src/data/ws/wsSource.ts (send("pingTeam", note)) and src/data/mock/mockSource.ts (no-op or simulated activity).
  3. Expose officeActions.pingTeam in src/store/office.ts.
  4. Register pingTeam: entry({ role: "operator", args: z.tuple([text(200)]) }) in server/commandPolicy.ts.
  5. Implement pingTeam: (note) => hub.activity("config", null, note) inside makeCommands() in server/commands.ts.
  6. Run pnpm typecheck && pnpm test architecture-invariants.
Hint: Why does architecture-invariants-test.ts fail if you skip step 4 or step 5?

Line 70 of scripts/architecture-invariants-test.ts runs assert.deepEqual(handlerKeys, policyKeys), plus TypeScript verifies server/commands.ts satisfies the mapped type Handlers from server/commandPolicy.ts. You cannot ship an unauthenticated or untyped command by mistake.

Lab 4 · Intermediate · Pure Logic & TDD

Write a Deterministic Scorer Rule

Goal: Follow ArimaOps's "pure logic first, zero I/O" pattern by adding a new free rule scorer (for example, large-diff or checking that a task's note isn't empty) and writing a test for it.

  1. Inspect SCORERS in src/data/scorers.ts and RULES in server/scorers.ts.
  2. Add a new rule id (e.g. "empty-handoff") to SCORERS with kind: "rule".
  3. Add its pure function to RULES in server/scorers.ts (checking (f.task.note ?? "").trim().length >= 10).
  4. Add an automated assertion in scripts/factory-test.ts (or a small test check) and run pnpm test factory.

Lab 5 · Advanced · MCP + Command Deck UI

Add a Role-Scoped MCP Tool & Deck Card

Goal: Register a new Lead-only MCP tool in server/mcp.ts and display data safely in the Command Deck UI without breaking invariants or design rules.

  1. In server/mcp.ts inside buildServer(), add a tool gated by if (isLead) (e.g. project_summary returning board + open task counts).
  2. Add the tool name to LEAD_ONLY_TOOLS in scripts/architecture-invariants-test.ts and verify pnpm test architecture-invariants passes across all 9 templates!
  3. In a UI component under src/ui/deck/, read snapshot stats using safe Zustand selectors (no ?? [] inside the selector callback!), stick strictly to font sizes 12/13/15/20/28 px and CSS tokens (text-accent, bg-[var(--surface-card)]), and preview in http://localhost:5178/?mock=1.
  4. Run pnpm build and pnpm test to confirm zero regressions.
Design & UI Checklist Before Considering Lab 5 Done
  • Uses Inter font and Material Symbols (<Icon name="…" />), no external fonts or hard-coded hex colors for accents.
  • Respects the 12 / 13 / 15 / 20 / 28 px size scale and weights 400 / 500 / 600.
  • Zustand selectors return stable primitives/references directly from state.
  • pnpm build and pnpm test both exit 0.
