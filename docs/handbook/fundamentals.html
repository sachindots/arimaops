CS & Stack Fundamentals

Every concept used inside ArimaOps explained from first principles—and linked directly to the exact file where you will see it in action.

1. Node.js Event Loop, TypeScript & "Parse, Don't Validate"

What it is: Node.js executes JavaScript on a single main thread using an event loop: slow work (disk reads, HTTP calls, spawning child processes, waiting on WebSockets) is handed off to the OS asynchronously so Node can serve dozens of browser tabs and agent hooks simultaneously without blocking.

  • Why process.on("unhandledRejection") sits in server/main.ts: Because one HQ process supervises every project and every terminal stream on your machine, an uncaught async failure in one background GitHub poll must log a warning—never crash Node and take down all running agents.
  • TypeScript as a shared wire contract: Both server/ and src/ import src/data/types.ts, src/data/model.ts, and src/data/source.ts. TypeScript checks shapes at compile time (pnpm typecheck), but TypeScript types disappear at runtime!
  • Parse, Don't Validate (Zod v4): Anything arriving over WebSocket or HTTP is untrusted JSON. Instead of checking if (typeof x === "string") inside 40 handlers, server/commandPolicy.ts runs Zod tuple schemas at the edge so every command handler in server/commands.ts receives guaranteed typed arguments or is rejected before running.
server/commandPolicy.ts — Boundary parsing with Zod
const engine = z.enum(["terminal", "stream"]);
const agentPatch = z.looseObject({
  name: z.string().max(200).optional(),
  mode: z.enum(["local", "sandbox", "container"]).optional(),
  engine: engine.optional(),
});

2. HTTP, Cookies, Same-Origin Policy & WebSockets

Why ArimaOps uses both HTTP and WebSockets:

ProtocolHow it worksWhere ArimaOps uses it
HTTP(S)Stateless request → response. Client asks, server replies and closes.Serving built dist/ assets, POST /api/login, GitHub webhooks, CLI hooks (POST /hook/...), MCP (POST /mcp), REST projects API.
WebSocket (/ws)Starts as HTTP, then upgrades to one persistent full-duplex TCP tunnel. Both sides push frames anytime.Streaming live terminal bytes, instant task/agent state deltas (OfficeEvent), and low-latency commands ({ cmd, args }) from UI to HQ.
  • Auth without leaking tokens in URLs: Opening http://127.0.0.1:7420/?token=... lets src/store/office.ts immediately POST /api/login to trade the URL token for an HttpOnly device cookie (hq_sid), then strips ?token= from the address bar via history.replaceState so screenshots and browser history never expose it.
  • Origin Check + CSP (APP_CSP in server/http.ts): Even if you are signed in to HQ in Tab 1, a malicious website in Tab 2 cannot open a WebSocket to 127.0.0.1:7420/ws because HQ verifies the browser's Origin header on upgrade, and sends Content-Security-Policy: default-src 'self'; script-src 'self'; frame-ancestors 'none' on HTML responses.

3. React 19, Unidirectional Reducers & Zustand Traps

The mental model: Your UI is a pure projection UI = f(state). Components never mutate snap.tasks directly. When you click "Assign", the UI sends a WebSocket command to HQ; HQ validates it, mutates the server's Hub, saves SQLite, and broadcasts an OfficeEvent; finally reduce(snap, event) in src/store/office.ts produces a new immutable snapshot object, triggering React to repaint only the affected components.

Critical Footgun in Zustand Selectors

Never create a fresh array or object inside a Zustand selector callback:

Wrong (causes infinite React render loop): useOffice((s) => s.snap?.tasks ?? []) — because [] !== [] on every store check.

Right: useOffice((s) => s.snap?.tasks) ?? [] — the selector returns the stable reference from the store, and the fallback happens outside.

4. SQLite, WAL Mode, Transactions & FTS5

Instead of requiring users to install Postgres, Redis, or Neo4j, ArimaOps uses Node 22.13+'s built-in node:sqlite (DatabaseSync). Everything lives in one 0600 file: ~/.arima/arima.db (plus per-project arima.db for doc rows).

  • WAL (Write-Ahead Logging): Enabled in server/lib/db.ts and server/lib/docs.ts via PRAGMA journal_mode = WAL;. Writes append to a separate -wal file before merging into the main DB, which means readers never block writers and a sudden crash (or SIGKILL) leaves the last committed state intact.
  • Numbered immutable migrations: MIGRATIONS in server/lib/db.ts is an append-only array of SQL scripts wrapped in BEGIN IMMEDIATE ... COMMIT transactions. Released migrations are never edited—only new steps are appended.
  • FTS5 (Full-Text Search): Rather than running vector embeddings or a graph server, memories mirrors text automatically via SQLite triggers into a virtual memory_text USING fts5 table so agent recall() searches run in microseconds in-process.

5. Terminals, PTYs, ANSI Codes & tmux

When you open an agent's terminal in the browser, you are not looking at a plain text file. Interactive CLIs like Claude Code draw full-screen TUIs (menus, spinners, colors, cursor jumps) using ANSI escape sequences inside a PTY (pseudo-terminal)—a kernel pair of virtual device descriptors (controller ↔ worker) that tricks a CLI into thinking a real human monitor/keyboard is attached.

  • @lydell/node-pty: Gives Node a controller handle to spawn a shell/CLI with terminal dimensions (cols × rows) and pipe raw ANSI output bytes over WebSocket to @xterm/xterm in the browser.
  • Why tmux wraps every agent: If Node spawned the CLI directly as a child PTY, restarting HQ for an upgrade would kill every running AI agent mid-edit. Running each agent inside a detached tmux session named hq-<project>-<agent> lets HQ restart and cleanly reattach to surviving agents (and lets you inspect any terminal from your shell via tmux attach).

6. Docker Bridges, HTTP CONNECT Proxies & iptables

Running autonomous AI coding agents with shell access requires tight blast-radius control. ArimaOps supports three isolation modes (local, sandbox via Docker Sandboxes microVMs, and container for plain Linux VMs without nested virtualization):

  • Dedicated Bridge (br-hq, 172.30.0.0/24): In Container mode (server/containers.ts), agents run on an isolated Docker bridge with container-to-container traffic disabled (icc=false). They can reach HQ only at the bridge gateway IP 172.30.0.1.
  • Allowlist Proxy (172.30.0.1:8420): Every container starts with HTTP_PROXY and HTTPS_PROXY pointing to HQ's egress proxy. For HTTPS, the CLI sends an unencrypted CONNECT api.anthropic.com:443 HTTP/1.1 tunnel request first; HQ inspects the hostname against BASE_ALLOW + the agent's allow/deny lists before opening a TCP pipe—without needing to break TLS encryption.
  • Mandatory Firewall Lock: Adding sudo iptables -I DOCKER-USER -i br-hq -j DROP prevents a rogue script inside a container from ignoring HTTPS_PROXY and dialing arbitrary internet IPs directly.

7. Model Context Protocol (MCP)

What it is: MCP is an open JSON-RPC protocol that lets AI CLIs discover external tools at startup (tools/list) and execute typed actions (tools/call). HQ embeds a stateless Streamable HTTP MCP server at POST /mcp (server/mcp.ts).

Why stateless per-request registration is clever: Every agent receives a tailored .mcp.json pointing to HQ with its own HMAC token and X-HQ-Agent header. When Claude or Codex calls /mcp, HQ looks up who the caller is and dynamically registers only the tools allowed for that role and project rules—a developer never even sees create_task or report_finding (unless findings are enabled).

9. Android WebView Bridges & Deep Links

Why WebMessagePort beats @JavascriptInterface: Classic Android WebView Java bridges inject Java objects globally—even if a page navigates or embeds third-party content. In android/app/src/main/java/com/arimaops/app/MainActivity.java, HQ creates a message port pair (createWebMessageChannel) and transfers one port only to the exact main-frame origin verified by ServerUrl.sameOrigin(), freezing window.ArimaNative in JavaScript. Combined with Firebase Cloud Messaging data payloads (PushService.java) and the arimaops://open intent scheme, tapping an alert on your phone jumps directly into the exact agent or Inbox drawer.
