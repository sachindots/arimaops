The 4 Core Ideas Behind ArimaOps

Before reading a single line of code, lock in the four architectural decisions that shape every file in the repository:

  • One HQ server owns everything on the machine: Instead of spawning one backend per repository, server/main.ts boots a single Node.js HTTP + WebSocket process (:7420) that loads every active project into memory as a Runtime and persists shared tables in ~/.arima/arima.db.
  • Real AI CLIs run outside Node in isolated sessions: ArimaOps does not reimplement an agent loop from scratch. Each agent is a real CLI process (Claude Code, Codex, Antigravity, Gemini CLI, OpenCode, Copilot) running inside a tmux session—optionally inside a Docker Sandbox VM or a locked-down Docker container—and communicating with HQ via hooks, Stream-JSON, and the Team MCP server.
  • Server is the single source of truth: The browser and Android app never invent business logic or bypass permissions. The React UI receives an initial OfficeSnapshot plus live OfficeEvent deltas over WebSocket, and sends back validated { cmd, args } commands enforced by server/commandPolicy.ts.
  • Gates instead of blind trust: Tasks move along stage pipelines (e.g., Spec → Plan → Build → Review → Merge) guarded by 11 concrete gate types (spec-approved, analyze, tests-ci, reviewer, second-opinion, evidence, pr-merged, scope-set, findings-report, file-delivered, owner-approval).

How to Read Any Feature in 5 Minutes

Whenever you want to understand how a button or setting works end-to-end, trace these 6 files in order:

  1. Types (src/data/types.ts & src/data/model.ts): Find the data structure and field names shared by server and UI.
  2. Contract (src/data/source.ts): Find the OfficeDataSource method signature and matching OfficeEvent union member.
  3. UI Dispatch (src/store/office.ts): Find the officeActions.* wrapper and how reduce(snap, event) updates Zustand state.
  4. Security Gate (server/commandPolicy.ts): Find the role requirement (viewer / operator / owner), stepUp flag, and Zod tuple schema.
  5. Server Handler (server/commands.ts): Read the exact server mutation, database write, and hub.emit(...) call.
  6. Verification Test (scripts/*-test.ts): Read the test file for that module—ArimaOps tests document edge cases and exact invariants clearly.
Two Essential Repo Commands

Run pnpm test to execute all 53 test scripts in scripts/*-test.ts (or pnpm test auth gates to run just two). Run pnpm build to typecheck both UI and server, build Vite, and bundle dist-server/ via esbuild.
